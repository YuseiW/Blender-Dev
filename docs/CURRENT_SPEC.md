## 1. 研究目的

Blenderを利用したアニメーション制作において、
絵コンテ・レイアウト・原画を現在のフレームと
対応付け、資料参照作業の負担を軽減する。

## 2. 現行システム構成

- Blenderアドオン＋PySide6管理GUI（外部Pythonプロセス）で実装する。
- 管理GUIのみ独立したPySide6ウィンドウで提供する。
- 画像・資料データはBlender内で保持し、管理GUIが操作を送信する。
- リファレンスビュアーにはBlender標準の
  別ウィンドウを利用する。
- 開発言語はPython（Blender API）。

※ D-005により、資料管理UIについて外部GUI方式を採用した。

## 3. データ構造

### Project
- プロジェクト名
- FPS（基本24fps）
- 画像プール
- 複数のCut
- 保存先

### ImageAsset
- UID
- 画像名
- ファイルパス

### Cut
- UID
- カット名
- Timeline開始フレーム
- 絵コンテ一覧
- レイアウト一覧
- 原画一覧

### ReferenceItem
- UID
- 参照画像ID
- 表示フレーム数
- 自由記述による指示

## 6. 現在の制約

- 専用ビュアーが開いている場合はそのImage Editorだけを同期する。
- ビュアーがない場合は互換性のため全Image Editorを同期する。
- JSONには一部のUI選択状態を保存していない。
- Windowsコンソールで日本語が文字化けする。
- chcp 65001は環境でフリーズが発生したため
  使用しない。

### Phase V-1：Viewer/Manager同一ウィンドウ切替

- V-0: Blenderカメラ背景画像の前面表示、不透明度変更はユーザー実機確認済み（POC）。本体への組み込みはV-4で実施。
- V-1: PySide6のQStackedWidgetで閲覧画面と既存Manager画面を切替。Managerの登録・保存・D&D等は維持。
- Viewerは読み取り専用・現在のSnapshotからプレビュー表示。画面切替時と「更新」でBlender最新状態を取得。
- Timelineに対する継続的な自動更新・表示設定トグル・カメラ重畳との接続はV-3/V-4の予定。
- 状態: コード準備済み。Blender/Windows実機での画面切替テスト待ち。

### Phase V-2：Viewerの基本表示・操作性

- Qt Viewerの画像表示をQGraphicsViewで実装し、ホイールズーム、ドラッグパン、全体表示、100%表示を提供。
- 原画・レイアウト・絵コンテ切替を継続し、現在フレームの登録資料をカテゴリカラーで強調する。
- 資料一覧の構成が変わらない更新では一覧を作り直さず、現在資料が切り替わるときだけ該当行へスクロールする。
- Viewerは閲覧専用。資料登録・編集・JSON保存は既存Managerが担当。
- カメラ重畳と自動同期の操作部品は、まだ無効（V-3/V-4で接続）。
- Phase V-1の画面切替はユーザー実機で動作成功（2026-11-17）。
- Phase V-2のWindows/PySide6実機動作は適用後に確認。

### Phase V-3：Timeline継続同期（2026-11-17）

- Phase V-2の6項目はユーザーがWindows/Blender上で全件成功を報告した。
- Blender側timerでProjectスナップショットを定期検査し、変更時のみ `state/latest.json` にアトミック書き込みする。
- Qt Viewerは表示中のみ通知ファイルを監視し、資料画像・指示文・強調表示を更新する。
- Manager入力画面は自動フレーム更新で再描画しない。復帰時に資料データが変更された場合のみ再描画する。
- Viewer左下の自動同期ON/OFFを接続し、OFF中は同Scene・Cut・カテゴリの最後の表示資料をUIDで保持する（資料順変更に対しても安定）。
- OFF中にカテゴリ・Cut・Sceneが変わるか、手動更新した場合は現在のBlenderフレームを採用する。
- 対応する旧Blender標準ビュアーは維持。カメラ重畳の統合はPhase V-4に残す。
- Phase V-3の実機検証は適用後に行う。

### Phase V-3.1：同期復旧とViewerカット切替（2026-11-17）

### Phase V-3.2：Qt同期制御とNパネル整理（2026-11-17）
- 3D ViewのAnimRef Nパネルは「AnimRefを開く」ボタンのみ。登録/編集はQt Manager、表示制御はQt Viewer。
- auto_syncの真値はScene.animref_project.auto_sync（Blender側）に一本化。Qt側の操作を既存set_auto_sync要求へ送信。
- 通信中の自動同期操作は最後の要求をキューに保持し、応答後に送信する。応答前のライブ状態でチェック表示を巻き戻さない。
- 旧Image Editorビュアーは回帰試験完了まで維持。V-5で最終整理する。
- Blender 5.2実機検証は未実施。

### Phase V-4：カメラ重畳のQt Viewer統合（2026-11-17）

- カメラ背景画像のFRONT表示（Blender 5.2でPoC実機成功）を利用。
- Viewerからカメラ重畳ON/OFF、不透明度0〜100%を操作する。初期設定はOFF・50%。
- QtからBlenderへのJSON要求／応答を再利用する。設定値はSceneのBlenderプロパティに保持し、AnimRef ProjectのJSON保存形式は変更しない。
- 自動同期ON: カメラ重畳もフレーム・カット・カテゴリに追従。OFF: 同じカット・カテゴリ・カメラで最後の画像を維持。明示更新や選択変更では更新。
- 既存カメラ背景画像は削除・変更しない。AnimRefの所有タグを付けたレイヤーだけを解除し、元の背景表示設定を復元する。
- カメラビューでの位置合わせはFIT（縦横比維持）、最終レンダリングへは含めない。
- 旧3D Nパネルは起動ボタンのみ。旧Blender Image EditorビュアーはV-5まで残す。
- 状態: ソース契約／Blender模擬試験／IPC模擬試験済み。Windows/Blender 5.2実機は未検証。
